## 修复：通关/失败后不返回主界面（动画回调不触发导致流程卡死）

- 现象：通关与失败都停在战斗界面，结算面板出不来（或点「再来一局/领取」无反应）。
- 根因（`%LOCALAPPDATA%/Unity/Editor/Editor.log` 实测）：日志出现 230 次 `Invalid Layer Index '-1'` 与 `Animator.GotoState: State could not be found`，调用栈是 `GameCommand:87 → BATTLE_PASS_GAME → BattleViewMediator:185 → AnimatorWidget.Play`。这些 2019 年旧格式 AnimatorController 在 Unity 2022 下运行时 state 查不到（layerCount/状态失效），`AnimatorWidget.Update` 里 `GetCurrentAnimatorStateInfo().normalizedTime` 永远是 0，**动画结束回调永不触发**：
  - 通关：`anim_battleview_level_in` → `anim_battleview_level_nextlevel` 的回调里才 `ShowView("RESULT_VIEW","PASS_INIT")`，回调不来 → 结算面板不出现。
  - 失败：点「再来一局」→ `GAME_RESULT` → `BATTLE_END_GAME` → `animWidgetProgress.Play("anim_battleview_progress_move", cb→RESULT_INIT)`，同样卡住。
- 修复①`AnimatorWidget.cs`：`Play(name, callback)` 增加保底。controller 丢失（`runtimeAnimatorController == null || layerCount <= 0`）时立即回调；否则用 `HasState` 检查状态，并起 3 秒 realtime 看护（`Timer.Register(..., null, false, true)`），到点若 `shortNameHash` 不匹配且 `normalizedTime <= 0.01`（说明动画根本没开始）就强制回调。用 `_fallbackToken` 防止旧看护误触发新回调；`Update` 与兜底统一走 `InvokeFinishCallback()` 保证只回调一次。
- 修复②时间缩放加固：`BATTLE_EXIT_GAME` 先 `Time.timeScale = 1f` 并用 realtime 计时器（原来 scaled，广告/暂停把 timeScale 留在 0 时永不触发 → 点了没反应）；`GAME_PASS` 的 1.5s、`DelayOpenResult` 的 1s 也改 realtime；`GAME_CONTINUE`（复活）开头与 `ResultViewMediator.OnClickAgain()` 开头都强制 `timeScale = 1f`（后者后面接 DOTween `LayerShake` 回调发 `GAME_RESULT`，timeScale=0 会让抖动动画永不完成）。
- 验证方式：运行后看日志——若打印「Animator 没有加载到 Controller」或「找不到该状态」，说明旧 controller 在 Unity 2022 下确实失效；此时结算流程仍能靠兜底走通。彻底修 controller 需在 Unity 里打开对应 .controller 重新保存以迁移格式。
